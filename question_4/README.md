# Plot-Twist Generator

Vanilla RNN vs LSTM language models trained on TinyStories and used to generate story continuations.

**Course:** DSL 504 NLP Group Assignment 2, Question 4

## 1. Overview

| Model | Architecture |
|---|---|
| Vanilla RNN | Embedding -> `nn.RNN` -> Linear |
| LSTM | Embedding -> `nn.LSTM` -> Linear |

Both models share the vocabulary, data splits and training setup. They are compared on loss, perplexity, lexical diversity, repetition and generated story continuations. Decoding strategies: greedy, temperature sampling, top-k sampling.

## 3. Data preparation

Dataset: [roneneldan/TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories). The raw dataset is not included in the repo or the submitted archive. The supplied 1,000-story validation and test token-ID subsets are included for evaluation. The training subset is not included; preprocessing can recreate it in a working copy.

```cmd
python -m src.preprocess
```

| Setting | Value |
|---|---|
| Source | First 22,000 stories of the TinyStories train stream |
| Stories (train / val / test) | 20,000 / 1,000 / 1,000 |
| Split level | Story-record level, shuffled with seed 42 before train/validation/test slicing |
| Tokenisation | Word-level regex, lowercased, curly quotes normalised |
| Vocabulary | Train split only, min frequency 5, max 10,000 (6,695 words after filtering) |
| Special tokens | `<pad>=0 <unk>=1 <bos>=2 <eos>=3` |
| Max story length | 200 tokens (longer stories truncated, no `<eos>` appended) |
| Seed | 42 |

**Run environment record.** The training histories preserve seed, parameter count, losses/perplexities and elapsed seconds, but not the actual runtime device or hardware model and not Python/PyTorch/CUDA/`datasets` versions. The training code automatically selects CUDA when available, otherwise CPU. `requirements.txt` is unpinned; `COLAB_STEPS.md` mentions a T4 only as a suggested setup. The original environment cannot be identified from the supplied run artifacts. Record exact details from the original Colab/runtime logs if available; otherwise state that they were not recorded.

Each story record is partitioned before token sequences are constructed; each record is its own sequence (`<bos> ... <eos>`). The code does not intentionally reuse one list entry across splits. It does not retain source story IDs or run an exact/near-duplicate audit, so duplicate text represented by separate upstream records cannot be ruled out.

The loader streams the Hugging Face `train` split, takes its first 22,000 records, shuffles those records with seed 42, and then creates 20,000/1,000/1,000 story-level train/validation/test slices. These validation and test subsets are internal held-out splits from the publisher's `train` split, not the dataset publisher's official validation/test splits. The dataset revision and upstream record IDs were not saved. Actual split leakage has not been established from the available code; because no duplicate/near-duplicate audit was run, it also cannot be categorically ruled out.

Batches are padded with `<pad>`. Loss uses `CrossEntropyLoss(ignore_index=pad_id)`, so padding is never counted.

| Path | Content |
|---|---|
| `data/processed/{val,test}.pt` | Supplied held-out token-ID sequences; training data is regenerated by `preprocess` |
| `artifacts/vocab.json` | Vocabulary |
| `artifacts/data_stats.json` | Sizes, vocab size, unk rate, truncation |

| Split | Stories | Tokens | Avg length | `<unk>` rate | Truncated stories |
|---|---|---|---|---|---|
| Train | 20,000 | 3,483,783 | 174.2 | 0.22% | 32.7% |
| Val | 1,000 | 173,213 | 173.2 | 0.34% | 30.7% |
| Test | 1,000 | 174,787 | 174.8 | 0.34% | 32.2% |

Known limitation: text cleaning does not remove some garbled characters in the raw data, so a few tokens such as `€` and `™` are in the vocabulary and appear in some generations.

## 5. Generation

Example commands (the `--model` option is required):

```cmd
python -m src.generate --model rnn --strategy greedy
python -m src.generate --model rnn --strategy temperature --temperature 0.5
python -m src.generate --model rnn --strategy temperature --temperature 0.8
python -m src.generate --model rnn --strategy temperature --temperature 1.2
python -m src.generate --model rnn --strategy top_k --top_k 10
```

Repeat with `--model lstm`.

| Strategy | Description |
|---|---|
| Greedy | Highest-probability token at every step |
| Temperature | Logits divided by T before sampling, T in 0.5, 0.8, 1.2 |
| Top-k | Sample from the k most probable tokens, k = 10 (default), T = 1.0 |

| Generation parameter | Value |
|---|---|
| Max new tokens | 80 (`--max_new_tokens`) |
| Stop rule | `<eos>` or max new tokens |
| Blocked tokens | `<pad>`, `<bos>` |
| Seed | 42 (`--seed`) |
| Prompts | 7, defined in `src/generate.py` (mystery, discovery, unusual character, problem to solve, and others) |

Output: one JSON file per run in `results/`, named `{model}_{strategy}_t{temperature}_k{top_k}.json`. Each record stores model, strategy, temperature, top_k, seed, prompt and output. For greedy runs the temperature value in the file name is ignored by the decoder.

## 6. Plot-Twist Challenge

```cmd
python -m src.challenge
```

Seven twist openings (exam paper with tomorrow's answers, robot with a message from its future self, detective solving a murder before it happens, village forgetting the previous day, letter from 100 years in the future, new kid who knows everyone's secrets, moon moving closer to the village), defined in `src/challenge.py`.

Each opening is run with both models and three strategies: greedy, temperature 0.8, top-k (k = 10). Two samples are generated per setting, so `results/plot_twist_challenge.json` has 84 records. Greedy decoding is deterministic, so its two samples are identical (70 unique outputs). Outputs are kept unedited, including failures. Max new tokens is 80 and the seed is set once at the start (42).

## 7. Evaluation

```cmd
python -m src.metrics
```

Output: `artifacts/metrics.json`.

| Metric | Definition |
|---|---|
| Val / test perplexity | `exp(mean per-token cross-entropy)` |
| Distinct-1 / Distinct-2 | Unique unigrams (bigrams) divided by total unigrams (bigrams) |
| Repetition rate | `1 - unique 3-grams / total 3-grams` per output, averaged |
| Average full-output length | Mean words in prompt + continuation (the generation function returns both) |
| Continuation-only length | Mean words after removing the exact prompt prefix |
| Short / overlong continuation counts | Continuations under 20 words / continuations of 180 words or more |

Notes on the generation metrics:
- They are computed over the 7 prompts in `src/generate.py` and 5 settings per prompt (greedy, T = 0.5, 0.8, 1.2, top-k), so 35 outputs per model.
- The original `average_generated_words_including_prompt` field counts the prompt and continuation together; it is not a continuation-only average.
- The original `premature_end_count_under_20_words` field also counted the prompt, so it cannot reliably identify short continuations. The updated metrics script now reports continuation-only lengths and the under-20 continuation count separately.
- Generation is capped at 80 new tokens. With the short prompts used here, the 180-word threshold is unreachable in practice; a zero overlong count is therefore expected by construction and is not informative.
- The 84 saved Plot-Twist Challenge records have separate continuation-only measurements in `artifacts/challenge_continuation_length_metrics.json`. They are not the same 35 general-prompt outputs used for the pooled metrics.
- The metrics script uses a seeded generation pass in its updated form. Perplexity is independent of sampling.

Per-strategy tables and analysis are in the report.

## 8. Human evaluation

```cmd
python -m src.human_eval
```

Creates `results/human_eval_blinded.csv`: 30 stories sampled from the challenge file (shuffled with seed 42) with model and strategy hidden. Raters score each story 1-5 for coherence, grammar, relevance and creativity/surprise.

The script does not write an answer key. Keep the mapping from sample ID to model and strategy in a separate file and do not give it to raters. Any ratings that were not collected from real raters are labelled as such in the report.

## 9. Limitations

- Small word-level models trained on a 20k-story subset, undertrained under the 10-epoch cap, single seed.
- Stories truncated at 200 tokens, so long-range structure is limited.
- Observed failures: repetition loops (especially greedy), drifting characters, lost prompt context, broken characters and `<unk>` tokens, nonsense at high temperature.
- Higher diversity and lower perplexity do not guarantee better storytelling.
- Small evaluation: 7 prompts, few samples per setting.

## 11. Reproducibility

1. Install dependencies.
2. `python -m src.preprocess`
3. `python -m src.train --model rnn` and `python -m src.train --model lstm`
4. `python -m src.plot_curves`
5. `python -m src.generate` runs (see section 5) for each model and setting
6. `python -m src.challenge`
7. `python -m src.metrics`
8. `python -m src.human_eval`

Seed 42 is used for data splitting, training and generation. Exact numbers can vary with PyTorch version, hardware and CUDA. The trained checkpoints, matching vocabulary and held-out evaluation tensors are included, so generation, metrics and rating-form creation can run without retraining.
